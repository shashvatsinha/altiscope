# Milestone 3: Different models, measurable results

Released as a **workflow demonstration**, not a quality evaluation. Parent:
[#6](https://github.com/shashvatsinha/altiscope/issues/6). Integrated into `main` by
[PR #83](https://github.com/shashvatsinha/altiscope/pull/83) on 2026-10-06 and tagged `m3`.
`m3` is a milestone tag, not a package-version bump or a package-registry publication.
[ADR-0013](../adr/0013-m3-workflow-release-scope.md) defines the claim boundary.

## What works

- **Versioned recipes.** A recipe freezes a prompt, model, provider endpoint, output
  contract and generation settings. Each version is immutable and hashed
  ([recipes](../M3-RECIPES.md), [ADR-0012](../adr/0012-recipes-and-comparison-runs.md)).
- **Comparison runs.** One frozen source (a PR snapshot or a manager aggregate) runs
  through several recipes. Each candidate has a prompt-only baseline control. Results,
  failures, token usage, cost and latency are saved separately from the generated text.
- **Independent assessment.** A second model can assess one exact successful result as a
  whole. It is optional and gated on known, distinct underlying model identities. The
  assessment stays hidden from a reviewer until an initial judgment is recorded.
- **Inspection and review.** `altiscope show-comparison` renders saved outcomes without
  executing anything. `altiscope comparisons review` runs a guided human review that commits
  the initial judgment before any reveal. `altiscope reviews export` writes a reloadable
  record.
- **Cost accounting.** Production call records are cache-aware, with a conservative
  OpenRouter cache-rate fallback.

## Real-source demonstration

Owner-approved run on saved public MarkItDown sources, through OpenRouter, with a
US$12 spending cap:

- Eight PRs plus one manager aggregate over those eight PR reports.
- 62 model calls, all with complete cost records.
- **US$1.009516** recorded spend.

The full 20-PR set was collected and frozen, but only these eight cases were run
(see [plan](../evaluation/m3-workflow-plan.md)). The exact local IDs, and the saved pages to
open, are in the [owner review handoff](../evaluation/M3-OWNER-REVIEW.md). Reproduce the
credential-free parts with the [walkthrough](../M3-WALKTHROUGH.md).

The eight cases were originally held out for a quality study. Their outputs are now
exposed, so they cannot serve as untouched holdouts later.

## Validation

Recorded at release, from [PR #83](https://github.com/shashvatsinha/altiscope/pull/83): GitHub
Actions CI passed on the M3 implementation PR, and the full local Postgres suite, Ruff lint
and format, strict Pyright and `git diff --check` passed. The M3 checkpoints in the
walkthrough and plan recorded 220 and 221 passing tests with Postgres; these are not
the current count.

The owner verified presentation and workflow behavior. The owner does not have MarkItDown
familiarity and made no source-level judgments.

## Limits

- **Not measured:** correctness rates, reader usefulness, assessor detection rates and
  manual effort savings. No qualified reviewers were available. The synthetic review
  records are fixtures, not human judgments.
- **Model identity.** The models used are mutable aliases. Stored recipe configuration and
  returned model IDs describe the observed calls, not a permanent model revision.
- **Cost figures** are configured-price estimates from recorded usage, not a provider bill.
- **Aggregate scope.** The manager aggregate is `single_step` over eight saved PR reports.
  It tests composition over saved inputs, not tree planning.
- Generation is synchronous, with no background queue.

## After M3

A qualified evaluation needs a new study with a newly versioned dataset and protocol,
fresh held-out cases, qualified reviewers and frozen recipes and sources.
The 2026-10-06 owner-approved [ADR-0014](../adr/0014-local-web-and-hosted-access.md)
defers this as optional future work rather than an M4/M5 release gate. M4 prioritizes
local web use; M5 adds hosted login and repository connections.

Tech-debt follow-up from the M3 code review is tracked in
[#65](https://github.com/shashvatsinha/altiscope/issues/65).
