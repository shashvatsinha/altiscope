## What works

Ask for merged work in one repository over an inclusive date window, choose an engineer,
manager, or executive view, and follow the resulting summary down to the exact input
report versions and original PR links. Regeneration preserves earlier results and
records the model, prompt, settings, and attempts at every level.

The owner revised provenance during this milestone: the application records all
supplied inputs. Models do not choose source references, and there is no coverage
percentage. [ADR-0011](../adr/0011-aggregate-report-provenance.md) is the current decision;
older coverage and citation requirements in GitHub child issues are superseded.

## Storage and behavior

Migration 0005 adds current aggregate report versions, input relationships to PR reports
or child reports, and links to the shared `llm_calls` history. Legacy aggregate-claim
tables are left untouched. Input data is checked against the exact saved report version
before publication. Each node is saved atomically; completed children and failed
attempts remain available if a later node fails.

Normal requests refresh selected GitHub PRs before consulting aggregate caches.
`--local-only` explicitly uses saved sources without claiming remote freshness. New
requests use latest successful input versions. `--regenerate` creates fresh aggregate
versions throughout the requested tree. Existing higher-level reports never change
or regenerate automatically.

## Limits

- The samples are synthetic recordings. They demonstrate the workflow, not live model
  accuracy or business outcomes. Owner acceptance is for inclusion of the examples;
  it is not a separate formal model-quality review.
- GitHub reads are not transactional across all PRs and endpoints. A refresh can detect
  many source changes but does not establish a perfectly simultaneous repository view.
- Request budgets use estimates. If actual intermediate outputs do not fit any configured
  model, the request stops; it does not silently trim them.
- Generation is synchronous. There is no background job queue or automatic crash recovery.
  Repeating a request can reuse completed nodes. Concurrent identical requests may both
  generate results; both versions are retained.
- Manual input-version selection, comparison UI, optional second-model review, and
  private organization access are later work.
